# 产品思维练习手册

这是一份持续追加的练习手册，不是一次性文章，配套笔记见[从会做需求到会判断问题](/notes/from-developer-to-product-thinking)。它不打算讲方法论，只是我每次练习时实际填写的模板集合。练习对象是真实业务数据，公开前必须脱敏。

## 使用方式

1. 每次练习复制一份"单次练习模板"，追加到练习日志或单独存档；
2. 按模板顺序填写，不允许跳过"事实"直接写"结论"；
3. 练习结束后，把可公开、可复用的部分回填到本手册对应章节，让手册慢慢变厚。

节奏上不强求频率，但建议每次练习控制在一个明确的小问题内，并且当场完成"事实 → 假设 → 证据 → 决策 → 验证"的完整闭环。宁可小题做完整，不要大题做一半——练习的目标是练判断的顺序，不是产出结论的数量。

## 安全边界：生产环境只读

所有练习在真实数据上进行，必须遵守：

- 只允许页面导航、查看、筛选和查询这类只读操作；
- 禁止直接调用或重放任何可能产生副作用的接口；明确禁止的操作包括但不限于：新增、编辑、删除、复制、启停、批量操作、导入导出、提交、重试、发布；
- 不外传原始后台截图；公开内容只保留结论和结构，不保留数值；
- 不出现公司名、项目名、后台地址、账号、接口路径、真实金额、内部人员信息；
- 拿不准能不能写的，默认不写。

## 指标口径核对清单

做任何比率、排名、对比之前，先过一遍：

- [ ] 分子定义：统计的是什么事件、什么实体（次数还是独立对象数）
- [ ] 分母定义：从哪个动作开始算，和分子是否同一阶段
- [ ] 统计阶段：前端上报、网关、服务端还是离线报表，各阶段是否有丢失
- [ ] 去重逻辑：同一对象重试、重复上报，算一次还是多次
- [ ] 时间口径：时区、自然日还是滚动窗口，延迟上报如何归属
- [ ] 维度口径：按什么维度聚合，维度值是否可能为空或重复

两个数字相除之前，必须能一句话说清分子、分母各自的来源。

## 问题优先级检查

看到"异常"先别排优先级，按顺序问：

1. 影响面：影响谁、什么量级、是否还在扩大；
2. 影响深度：阻断主流程，还是体验降级；
3. 可逆性：不处理的话，损失是否随时间累积；
4. 口径可信度：这个数字本身可信吗（先过口径清单）。

"看起来严重"和"确认严重"之间，隔着一张口径清单。

## 根因分析维度

拆解问题时，至少从下面几个维度各问一次，避免只盯着自己最熟的那一层：

- 业务侧：业务规则、目标人群、产品机制；
- 流量侧：来源、渠道、投放策略、出价与定向；
- 链路侧：监测、埋点、归因、各系统交接处；
- 内容侧：素材、落地页、衰减周期；
- 数据侧：口径、统计延迟、重复或丢失。

指标按问题选，不要求四类俱全：绝对值看规模（问题有多大），比率做横向比较（不同业务或计划之间谁更严重），分布（如单计划维度）用来定位（普遍现象还是个别失控），占比用来决定投入（值得花多少精力）。无论选了哪几个，最后都要能解释形成机制，不停在现象层。

## 方案的四类风险

任何方案（练习中只写方案不实施也一样）都评估一遍：

- 价值风险：问题是否真实、值得解决，结果对用户或业务是否真有价值；
- 易用性风险：用户能不能看懂、用起来，方案本身会不会成为新的门槛；
- 可行性风险：技术上能否实现，成本、对现有链路的侵入和回滚难度；
- 商业可行性风险：商业上是否成立，是否触碰平台规则、隐私和数据使用边界，是否损害其他业务。

另加一项横切检查——测量风险：方案上线后指标是否还可比、归因是否会乱、口径是否对得上。它不是第五类产品风险，而是做验证设计时每次都要单独过一遍的检查项。

## 上线前后验证

练习阶段不实施，但验证方案必须写完整，当作"真的要上线"来设计：

- 上线前：预期改动的指标、预期幅度、观察窗口、对照方式；
- 上线后：用什么信号确认有效、用什么信号触发回滚、多久复盘一次。

验证方案写不出来，通常说明决策本身还没想清楚。

## 决策日志模板

```markdown
### YYYY-MM-DD｜（决策主题）

- 背景与事实：
- 备选方案：1.  2.
- 选择的方案与理由：
- 当时掌握的信息 / 当时缺失的信息：
- 预期验证信号：
- 事后回看（日期 + 结论，回填）：
```

决策日志的价值在"当时"两个字：记录信息不全时的判断依据，避免事后用结果倒推当时的合理性。

## 复盘模板

```markdown
### 复盘｜（主题）｜YYYY-MM-DD

- 最初的判断是什么：
- 哪些被推翻了，被什么推翻的：
- 有没有"结论对、但理由错"的地方：
- 下次同类问题，第一步做什么：
- 需要沉淀回手册的内容：
```

复盘只回答一件事：下次遇到同类问题，哪一步可以更快、更准。

## 当前练习路线

按依赖顺序推进，前一步的输出是后一步的输入：

1. 业务链路图：先把业务到投手的完整链路画出来，产出一张环节图；
2. 指标树：在链路上挂指标，区分规模、比率、分布、占比，产出一份指标清单；
3. 订单失败问题简报：用口径清单写一份失败问题的说明，产出可给第三人读的简报；
4. 纯空耗根因分析：多维度拆解，并解释形成机制，产出根因假设和证据对照；
5. IAA 与付费收入的变现分析：按变现模型拆开看收入结构（本次练习对比的是广告收入与付费/充值收入，付费侧是否等同于通用概念 IAP 待确认），产出两种模型的关键差异表；
6. 方案与验证设计：选一个结论，写出方案和验证信号，产出方案草稿与验证清单。
