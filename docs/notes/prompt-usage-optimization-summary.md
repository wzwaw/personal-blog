# 提示词使用优化总结

这篇文档持续记录如何更有效地使用 AI 完成调查、实现、验证和复盘。内容只保留可公开、可复用的方法，不收录原始对话和具体业务信息。

## 通用提示词框架

```text
目标：
事实来源：
改动范围：
必须保留：
验收标准：
执行方式：能从现有资料和工具确定的直接调查并继续，仅在关键决策缺失时询问
```

不必每次机械填写所有字段。任务越复杂、影响范围越大，越值得明确事实来源、约束和验收标准。

## 2026-09-18 · 从过程指挥转向结果委托

**常见表达模式**

只告诉 AI 修改某个文件或字段，并提前指定未经验证的原因。AI 容易局限在局部代码，忽略调用链、兼容性和验收。

**推荐提示词**

> 完成这项功能。先核对需求和现有实现，分析完整调用链；保留未明确要求改变的行为。直接实现并执行与改动范围匹配的验证，最后说明证据、风险和未完成项。

**为什么更有效**

- 目标和验收比逐行指定修改方式更能发挥 Agent 的调查能力。
- 要求先核对证据，可以降低把猜测当成事实的概率。
- 明确“直接实现并验证”，能避免结果停留在建议或代码片段。

## 2026-09-18 · 为不同任务明确执行模式

**常见表达模式**

使用“看看”“检查一下”等表达，但没有说明只需要结论，还是需要继续修改并验证。

**推荐提示词**

> 先调查并给出证据，不修改代码；如果确认方案后我再让你实现。

或：

> 直接定位根因、实施修复并完成回归验证；不要只给方案。

**为什么更有效**

- 调查、诊断、规划和实现需要不同的终止条件。
- 提前声明执行模式，可以避免误改文件或只分析不落地。
